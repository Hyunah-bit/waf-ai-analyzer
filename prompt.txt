다음은 ModSecurity WAF가 차단한 감사 로그 여러 건이다.
각 로그는 "===== LOG #N =====" 로 구분되어 있다.
각 로그마다 정탐(실제 공격)인지 오탐(정상 요청)인지 판정하라.

파일 위치: /usr/local/bin/

[판정 기준 - 우선순위 순]
1. matched data가 공격 구문으로 문법이 완결되는가?
   가장 중요한 기준이다. 완결된다면 다른 조건과 무관하게 true_positive.
   예: "admin' OR '1'='1" -> SQL 조건이 항상 참이 되므로 완결됨
   예: "O'Brien" -> 따옴표만 있을 뿐 SQL 구문이 성립하지 않음
2. 걸린 파라미터가 자유 텍스트 필드인가, 형식 고정 필드인가?
   comment, content, message, bio 등은 자유 텍스트 -> 오탐 가능성 높음
   email, id, page, sort 등은 형식 고정 -> 공격 가능성 높음
3. 페이로드를 일반 데이터로 해석하면 말이 되는가?
4. 요청자가 사람인가 자동화 도구인가? (User-Agent, Referer, Cookie 유무)
5. anomaly score가 임계값 턱걸이(5)인가, 크게 초과하는가?

[주의사항]
- response.body는 WAF가 생성한 403 차단 페이지다. 판정 근거로 절대 쓰지 마라.
- error_messages는 audit_data.messages와 내용이 중복이다. 무시하라.
- 룰 949110, 980130은 점수 집계/차단 결정 룰이다. 실제 탐지 룰이 아니므로
  "여러 룰에 걸렸다"는 근거로 쓰지 마라.
- evidence에는 해당 로그에 실제로 존재하는 문자열만 그대로 인용하라. 변형 금지.
- 확신이 없으면 반드시 needs_review로 판정하라. 추측하지 마라.
- CWE는 확실한 경우에만 기입하고, 불확실하면 null로 두어라.

반드시 아래 JSON 형식으로만 응답하라.
"results" 배열에는 위 로그 각각에 대한 판정을 넣되,
"index"는 해당 로그의 번호(LOG #N 의 N)와 정확히 일치해야 한다.
로그가 5건이면 결과도 반드시 5건이어야 한다.

{{
  "results": [
    {{
      "index": 1,
      "verdict": "true_positive | false_positive | needs_review",
      "confidence": 0.0에서 1.0 사이 숫자,
      "attack_name": "공격명 (예: SQL Injection 인증 우회 시도)",
      "cwe_id": "CWE-89 형식 또는 null",
      "cwe_name": "CWE 이름 또는 null",
      "reason": "판정 근거를 2~4문장으로 서술",
      "evidence": ["해당 로그에 실제로 존재하는 근거 문자열들"]
    }}
  ]
}}
